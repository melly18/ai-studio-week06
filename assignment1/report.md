# 프롬프트 3기법 비교 리포트

## 1. 과업 정의
- 선택: 고객 리뷰 분류
- 분류 항목과 긴급도 기준: 리뷰를 배송/품질/가격/서비스/기타로 분류한다. 긴급도는 1~3의 정수값을 가지는데, 부정적인 리뷰일수록 긴급도를 높게 본다. 단순히 개인적인 선호로 인한 불만보다는 구체적 수치와 같이 객관적인 근거를 가질수록 긴급한 리뷰라고 판단한다. 근거에 대해서는 고객의 피해가 크고 공급자 측의 잘못이 명백할수록 중요하게 본다.
- 출력 형식: {"type": ..., "urgency": ...}

## 3. 프롬프트 전문
### Zero-shot  
당신은 고객 리뷰 분석 전문가입니다.  
규칙:  
1\. 리뷰를 반드시 [배송, 품질, 가격, 서비스, 기타] 중 하나로 분류한다.  
2\. 긴급도는 1~3의 정수값을 가지며, 그 판단 기준은 다음과 같다.  
- 부정적인 리뷰일수록 긴급도를 높게 본다.  
- 구체적 수치 등 객관적인 근거를 가질수록 긴급한 리뷰다.
- 근거 중 고객의 피해가 크고 공급자 측의 잘못임이 명백할수록 중요하게 판단한다. 

3\. {"type": "...", "urgency": 1~3}의 출력 형식 외의 인사말이나 설명을 덧붙이지 않는다.  


### Few-shot  
다음 형식으로 리뷰를 분류하세요.  
리뷰: "어깨 실밥이 다 뜯어져서 왔습니다. 당장 내일 입어야 했는데... 환불은 받았지만 정말 실망이네요."  
출력: {"type": "품질", "urgency": 2}  
리뷰: "사이즈 문의했더니 상담원이 정말 친절하게 알려주시더군요. 덕분에 잘 구매했습니다."  
출력: {"type": "서비스", "urgency": 1}  
리뷰: "쾅 소리가 나서 보니 택배가 도착해 있더군요. 다행히 깨지진 않았지만 이렇게 상품을 대충 취급하는 태도는 정말 실망이네요."  
출력: {"type": "배송", "urgency": 2}  
리뷰: "할인 기간이라 좋다고 구매했더니 왜 원래 가격으로 결제되는거죠? 장사 이런식으로 하시면 안 되죠-- 문의 넣었으니 빨리 처리 부탁드립니다."  
출력: {"type": "가격", "urgency": 3}  
리뷰: "가격이 싸서 기대를 안 하긴 했지만 해도해도 너무하네요. 색도 생각보다 별로고 오래 쓰지도 못합니다. 비추."  
출력: {"type": "품질", "urgency": 1}  

### CoT  
다음 고객 리뷰를 분류하고 긴급도를 판단하세요.  
긴급도 기준:  
- 부정적인 리뷰일수록 긴급도를 높게 본다.  
- 구체적 수치 등 객관적인 근거를 가질수록 긴급한 리뷰다.
- 근거 중 고객의 피해가 크고 공급자 측의 잘못임이 명백할수록 중요하게 판단한다. 

리뷰: "..."
다음 단계로 추론하며 과정을 기록한 뒤 마지막 줄에는 결론만 쓰세요.  
1단계: [배송, 품질, 가격, 서비스, 기타] 중 하나로 리뷰 분류  
2단계: 리뷰의 긍정/부정 판단 후 감정의 강도 파악  
3단계: 부정적인 표현에 대해 구체적인 근거가 있는지 판별  
4단계: 근거가 있다면 고객의 피해와 공급자 귀책 정도를 판단  
5단계: 긴급도 기준에 맞춰 1~3의 긴급도 부여
결론: {"type": "...", "urgency": 1~3}의 JSON 데이터

## 6. 분석
- 형식 준수: 세 가지 기법 모두 정확한 형식을 준수하여 답변을 출력하였다.
- 분류 정확성: 안타깝게도 두 가지 애매 사례에서 세 기법 모두 정답을 맞히지 못했다. 우선 3번 먼저 살펴보자면 분류를 맞힌 기법이 하나도 없긴 하지만 애초에 분류 자체가 애매하기 때문에(나는 이런 정답을 도출했지만 다른 사람의 판단은 다를 수 있다) 긴급도를 기준으로 정확성을 판단할 수 있을 것이다. 이렇게 기준을 완화하면 Zero-shot과 CoT가 정답을 충족한다.  
4번은 각 기법을 총 3번 실행했는데, Few-shot이 2번째, 3번째 실행에서 정답을 맞혔다.
- 일관성: 5번 항목을 통해 4번 케이스를 3번씩 실행했는데, Zero-shot은 분류가 한 번 바뀌었고 Few-shot은 긴급도가 한 번 바뀌었으며, CoT는 모두 동일한 결론을 도출했다.
- 비용: Zero-shot과 Few-shot은 출력 규칙에 맞게 정답 JSON 데이터만 한 줄 출력하지만, CoT는 사고 과정을 함께 출력하고 마지막 줄에 JSON 데이터를 한 줄 출력하기 때문에 두 기법에 비해 출력 토큰이 정말 많아 비용이 비싸다. 입력 토큰의 경우 Zero-shot이 두 기법보다 미세하게 적지만 규칙이 늘어날 수 있기 때문에 입력 보다는 출력 토큰이 중요할 듯하다.

## 7. 결론 — 우리 팀이 쓸 기본 전략
정답률을 따지자면 Few-shot이 가장 좋을 수 있지만, 이는 현재 예시의 규모가 작고 문제가 비교적 쉽기 때문일 것이다. 즉 데이터 규모가 커지고 문제가 복잡해지면 예시로 알려주는 사항 외의 것들이 많아서 모든 케이스를 적절하게 처리하지 못할 것이다. 이를 해결하기 위해서 많은 예시를 넣는다면 되겠지만, 그 경우 입력 토큰이 지나치게 커지기 때문에 비용 측면에서 비효율적이다.  
우리 팀은 분석과 추천을 목표로 하기 때문에 다양한 입력이 들어올 수 있어 Few-shot보다는 Zero-shot과 CoT가 후보가 될 수 있고, 그 중에서도 추천 기능이 있기 때문에 추론 과정을 알려주는 CoT가 가장 적절하다고 생각한다. 비용이 많이 들기는 하지만 논리적인 흐름으로 사고하고 일관적인 답변을 내놓기 때문에 사용자의 신뢰를 올려줄 수 있을 것 같다.
